# Cookie 设置 PRD（欧盟版）

| 页面名称 | 链接 |
| --- | --- |
| Cookie 同意 | `#/cookies-consent` |
| Cookie 偏好中心 | 首访横幅 → 管理首选项；登录后 → 设置 → Cookies 设置 |

---

## 一、背景与目标

### 1.1 背景

现有页面以登录窗口和底部横幅展示 Cookie 选项。首次访问时，路由守卫要求用户先做出选择，功能和性能类默认开启，隐私政策入口目前为占位提示。

### 1.2 目标

1. 用户可一键接受或拒绝，也可按用途选择，跳过选择后仍可登录并使用核心功能。
2. 可选技术仅在对应目的取得有效同意后启用。用户可随时修改或撤回。

## 二、术语与概念

| 概念 | 说明 |
| --- | --- |
| 严格必要 | 为完成通信或提供用户明确请求的服务所严格必需的终端读写 |
| 可选用途 | 功能、性能分析、定向广告。涉及终端读写的 Cookie、Local Storage 和第三方 SDK 均纳入控制 |
| 撤回 | 用户关闭此前允许的用途，或通过「全部拒绝」撤回所有可选用途 |

## 三、用户与场景

| 角色 | 场景 | 使用功能 |
| --- | --- | --- |
| 首次访客 | 希望直接登录，或只允许特定用途 | 跳过横幅、全部拒绝、管理首选项 |
| 回访用户 | 希望核对选择或撤回同意 | Cookie 设置、全部拒绝 |

## 四、需求范围总览

首次访问横幅 → Cookie 偏好中心 → Cookie 政策。登录前后共享偏好，并在登录页、业务页及独立落地页统一执行。

## 五、功能需求

### 5.1 入口与页面结构

| 入口 | 页面要求 |
| --- | --- |
| 首次访问 | 保留底部横幅，取消拦截登录及业务操作的强制跳转和遮罩。首层展示「全部接受」「全部拒绝」「管理首选项」，接受与拒绝同等醒目 |
| 管理首选项 | 复用现有抽屉。必要项固定开启，三类可选项首次默认关闭，已有有效选择时回显 |
| Cookie 设置 | 登录页新增常驻入口，登录后保留「设置 → Cookies 设置」。从两处均可查看选择并一键全部拒绝 |
| Cookie 政策 | 横幅和偏好中心均可打开正式政策，按项披露名称、用途、提供方、有效期及第三方访问情况 |

### 5.2 操作规则

| 操作 | 结果 |
| --- | --- |
| 全部接受 | 启用已披露的全部可选用途 |
| 全部拒绝 | 仅保留严格必要项，记住拒绝 |
| 确认我的选择 | 仅启用明确选中的可选用途 |
| 关闭或忽略 | 保留此前有效选择，首次访问仅运行严格必要项 |
| 撤回 | 立即停止对应脚本及终端读写，清理站点可控的相关标识 |

## 六、数据与业务规则

- 统一记录各用途选择、操作时间及用户所见的告知版本，支持举证。旧版 `ms_cookie_consent=1` 和 `ms_settings` 默认值无法证明有效同意时，仅运行严格必要项。
- 有效选择期间保留接受和拒绝。记录失效或用途实质变化后，对受影响的用途重新征求同意。保存期限按上线成员国规则确定。
- 在页面加载、路由切换和第三方标签初始化前校验偏好，避免可选脚本先执行。

## 七、状态与边界

| 验收场景 | 预期结果 |
| --- | --- |
| 清空站点数据后访问登录页、业务深链或 `/lift-activation` | 可继续访问。存储及网络请求中无可选追踪 |
| 全部拒绝后刷新并登录 | 拒绝状态保留，登录及核心功能可用 |
| 仅同意性能分析 | 仅严格必要项和性能分析生效 |
| 登录前后撤回并刷新 | 对应读写和追踪请求停止，刷新后保持关闭 |
