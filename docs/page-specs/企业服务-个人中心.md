# 企业服务-个人中心 页面规格

源文件（旧原型，只读）：

- `工作台.html` L125–217（`#v-personal`）
- `wb.js` L370–512（`PC_TABS` L373–377、`renderPC` L379–412、页签切换 L414–419、行内编辑与换绑 L421–452、通知邀请 L454–462、修改密码 L464–512）；简易弹窗 `dialog()` L58–83；启动 `renderPC()` L704

两入口均在 `工作台.html` 内切换视图，不跳页。外壳与 Toast、简易弹窗规格见《公共-外壳与菜单.md》。

## 1. 页面结构

```
.pc（flex，min-height: calc(100vh - 48px)）
├─ .pc-nav#pc-nav   左侧页签栏，宽 240px，底 --bg-soft，padding 16px 16px 24px
│    ├ 个人信息（user 图标）
│    ├ 修改密码（key 图标）
│    └ 通知邀请（mail 图标）
└─ .pc-body          右侧内容，padding 24px 32px 40px
     ├ [data-pane=info]   个人信息
     ├ [data-pane=pwd]    修改密码
     └ [data-pane=invite] 通知邀请
```

页签项 `.pc-nav-i`：高 50px，`padding:0 16px`，圆角 6px，`gap:10px`，14px，`--ink-2`；hover `--ink-1`；选中 `.on`：白底、`--theme`、600；图标 15×15。

页签规则：

- 默认 `state.pcTab = 'info'`。
- 点击 → 设置 `state.pcTab` → `renderPC()` 整体重绘（左栏 + 所有 pane 的显隐与数据）。
- 页签状态仅内存保存：切到其他菜单再回来保持；刷新回到「个人信息」。
- 切换页签不重置修改密码表单内容。

通用标题 `.pc-h`：16px 700，`margin:0 0 14px`。

### 2.2 行内编辑（姓名 / 业务职责）（wb.js L423–434）

点击笔形图标弹出简易弹窗：

| 字段 | 弹窗标题 | 输入框初始值 | placeholder |
|---|---|---|---|
| name | `修改用户姓名` | 当前 `DB.user.name` | `请输入`（默认） |
| role | `修改业务职责` | 当前 `DB.user.role` | `请输入`（默认） |

- 无描述文字；输入框自动聚焦并全选；按钮 `取消` / `确定`；Enter = 确定。
- 「确定」取 `value.trim()`：
  - 为空 → Toast（err）`内容不能为空`（弹窗已关闭，修改不生效）；
  - 非空 → 写入 `DB.user[字段]` → 重绘个人中心 → 若为姓名，另同步顶栏 `#user-txt` 并重算工作台问候语 → Toast（ok）`修改成功`。
- 无长度、字符校验；值与原值相同也提示「修改成功」。
- 「业务职责」是自由文本输入，不是下拉选择。
- 修改仅存于内存，**刷新丢失**，不写 localStorage。

### 2.3 换绑手机号 / 邮箱（wb.js L436–451）

| 项 | 手机号 | 邮箱 |
|---|---|---|
| 弹窗标题 | `换绑手机号` | `换绑邮箱` |
| 描述 | `本地演示：直接填写新的手机号即可。` | `本地演示：直接填写新的邮箱即可。` |
| 输入框初始值 | 空 | 空 |
| placeholder | `请输入新手机号` | `请输入新邮箱` |
| 校验（对 `trim()` 后的值） | `/^1\d{10}$/`（1 开头共 11 位数字） | `/^[^@\s]+@[^@\s]+\.[^@\s]+$/` |
| 校验失败 Toast（err） | `手机号格式不正确` | `邮箱格式不正确` |
| 成功写入 | `DB.user.phone = v.slice(0,3) + '****' + v.slice(7)`（如 13812345678 → `138****5678`） | `DB.user.email = v`（原样） |
| 成功 Toast（ok） | `换绑成功` | `换绑成功` |

- 校验失败时弹窗已关闭，需重新点击「换绑」。
- 无验证码、无原手机号/邮箱验证、无「与原值相同」校验（代码中未体现）。
- 取消 / 点遮罩：关闭，无提示。
- 仅内存，刷新丢失。

## 3. 页签二：修改密码（工作台.html L154–202，wb.js L464–512，app.css L366–391）

### 3.1 结构

- 头部 `.pw-hd`（`max-width:420px`，居中，左对齐文本，下距 16px）：
  - 标题 `修改密码`（`.pc-h`，内联 `margin-bottom:6px`）
  - 副标题 `为了您的账号安全，请定期修改密码`（13px `--ink-3`，内联 `margin:0`）
- 表单 `form#pw-form.pw`（`autocomplete="off"`，`max-width:420px`，居中，1px `--line` 边框，圆角 8px，`padding:24px`）：

| 顺序 | 标签（带红色 `*`） | 控件 | id | placeholder | 错误位 |
|---|---|---|---|---|---|
| 1 | `验证方式` | 三个胶囊单选：`旧密码验证`（默认选中）/ `短信验证码` / `邮箱验证码` | `#pw-rads`，`data-m` = `old` / `sms` / `mail` | — | — |
| 2 | `原密码`（随验证方式变化，见 3.2） | 输入框 + 眼睛图标 | `#pw-old` | `请输入` | `#er-old` |
| 3 | `新密码` | 密码输入框 + 眼睛图标 | `#pw-new` | `请输入` | `#er-new` |
| 4 | `确认密码` | 密码输入框 + 眼睛图标 | `#pw-re` | `请输入` | `#er-re` |
| 5 | — | 提交按钮 `确认修改`（主按钮，满宽） | — | — | — |
| 6 | — | 按钮 `重置`（满宽，左侧刷新图标） | `#pw-reset` | — | — |

样式要点：

- `.fld` 下距 18px；标签 13px 600，下距 9px；`*` 为 `--theme`，右距 3px。
- 单选 `.rad`：三等分，高 34px，1px `--line-2` 边框，圆角 17px，13px `--ink-2`；hover 字色 `--theme`；选中 `.on` 边框与字色 `--theme`；`gap:12px`。
- 输入框 `.ipt`：高 34px，圆角 4px，`padding:0 34px 0 12px`，13px；focus 边框 `--theme` + `0 0 0 2px rgba(198,0,11,.08)`；错误态 `.bad` 边框 `#f5222d`。
- 眼睛 `.eye`：`right:10px; top:9px`，16×16，`--ink-4`。
- 错误文案 `.err`：`#f5222d`，12px，上距 6px，`min-height:16px`（始终占位）。
- 「确认修改」与「重置」均为 `.btn` 满宽 36px；「确认修改」自带 `margin-bottom:10px`。

### 3.2 验证方式切换（wb.js L465–477）

`VERIFY` 映射（wb.js L465）：

| data-m | 第 2 行标签 `#lb-verify` | `#pw-old` 的 type | 眼睛图标 |
|---|---|---|---|
| `old` | `原密码` | `password` | 显示 |
| `sms` | `短信验证码` | `text` | 隐藏（`display:none`） |
| `mail` | `邮箱验证码` | `text` | 隐藏 |

切换时：更新选中样式 → 改标签与 type → **清空 `#pw-old` 的值** → 清空 `#er-old` 文案。新密码、确认密码不受影响。

- 短信 / 邮箱模式下**没有「获取验证码」按钮**，也无倒计时、无验证码位数校验（代码中未体现）。
- placeholder 始终为 `请输入`。
- 当前模式存于 `state.pwMode`（默认 `old`），仅内存。

### 3.3 密码显隐（wb.js L479–485）

- 点击眼睛：对应输入框 `type` 在 `password` ↔ `text` 间切换；显示明文时眼睛 `opacity:.9`，否则恢复默认。
- 图标本身不变（始终为带斜杠的「闭眼」图形，只改透明度）。
- 三个输入框各自独立。

### 3.4 提交校验（wb.js L488–506）

提交（点「确认修改」或在输入框内回车）时，先清空三处错误文案并移除页面上所有 `.ipt` 的 `.bad`，然后**三项同时校验**（不短路，可同时出现多条错误）：

| 字段 | 取值 | 规则 | 错误文案（逐字） |
|---|---|---|---|
| 验证项 `#pw-old` | `value.trim()` | 非空 | `请输入原密码` / `请输入短信验证码` / `请输入邮箱验证码`（= `'请输入' + VERIFY[mode][0]`） |
| 新密码 `#pw-new` | 原值（**不 trim**） | 1. 非空 | `请输入新密码` |
| | | 2. 长度 8–20，且含至少 1 个英文字母 `[A-Za-z]` 和至少 1 个数字 `\d` | `密码需 8-20 位，且同时包含字母和数字` |
| 确认密码 `#pw-re` | 原值 | 与新密码**严格相等** | `两次输入的密码不一致` |

- 出错字段输入框加 `.bad` 红框。
- 边界：新密码与确认密码都为空时，确认密码**不报错**（两空串相等），只报「请输入新密码」。
- 新密码不合规但两次一致时，只报新密码错误。
- 不限制特殊字符 / 空格 / 中文（只要求含字母和数字）。
- 不校验原密码正确性、不校验新旧密码是否相同（代码中未体现）。
- 输入过程中无实时校验；错误只在下次提交、点重置或（仅 `#er-old`）切换验证方式时清除。

全部通过：`form.reset()` 清空三框 → 清空错误 → Toast（ok）`密码修改成功（本地演示，未提交服务器）`。验证方式保持不变。

### 3.5 重置（wb.js L507–512）

- `form.reset()` 清空三个输入框 → 清空三处错误 → 移除 `.bad` → Toast（info）`已重置`。
- 不重置验证方式、不恢复输入框 type（眼睛状态保留）。

## 4. 页签三：通知邀请（工作台.html L205–213，wb.js L405–411、L454–462）

### 4.1 结构

- 顶部页签条 `#iv-tabs`（flex，`gap:10px`，下距 8px）：
  - `全部(0)`（默认 `.on`，`data-f="all"`）
  - `已处理(0)`（`data-f="done"`）
  - `待处理(0)`（`data-f="todo"`）
  - 右侧蓝字链接 `查看规则说明`（`#iv-rule`，`margin-left:auto`，13px，hover 下划线）
- 内容区 `#iv-body`

页签样式 `.iv-tab`：高 30px，`padding:0 16px`，1px `--line-2` 边框，圆角 15px，13px `--ink-2`；选中边框与字色 `--theme`。

### 4.2 数据与渲染

- 数据：`DB.invites = { all: 0, done: 0, todo: 0, rows: [] }`（data.js L139）。
- 页签文案由 `renderPC()` 生成：`全部(N)` / `已处理(N)` / `待处理(N)`，N 取 `all` / `done` / `todo` 字段（与 rows 长度无关）。
- `rows` 为空 → 空状态：`.empty`（`padding:90px 0`，居中，13px `--ink-4`）内含 `box` 图标（54×54，`opacity:.45`，下距 14px）+ 文案 `暂无数据`。
- `rows` 非空 → `#iv-body` 被置为空字符串（**不渲染任何行**，行结构代码中未定义）。

### 4.3 交互

- 点击页签：只切换 `.on` 高亮，**不做任何过滤或重绘**。
- 页签高亮仅 DOM 状态；`renderPC()` 重绘时只改文字不重置高亮。
- 点击「查看规则说明」→ 简易弹窗：
  - 标题 `规则说明`
  - 描述 `收到他人发起的租户邀请后，可在此处处理。处理结果会同步到通知列表。`
  - 按钮 `取消` / `确定`，均只关闭。
- 无接受 / 拒绝邀请操作（代码中未体现）。

## 5. 数据与状态汇总

- `DB.user` 结构（data.js L8–15）：`{ name, phone(脱敏), email, role, created('YYYY-MM-DD HH:mm:ss'), lastLogin(字符串，无值为 '-') }`。
- 内存状态：`state.pcTab`（默认 `info`）、`state.pwMode`（默认 `old`）、`DB.user` 的修改。
- 本页**不读写任何 localStorage 键**；所有修改刷新即丢失。
- `renderPC()` 调用时机：启动、切换页签、行内编辑成功、换绑成功。

## 6. 原型中的疑似缺陷或不一致

1. 所有校验失败都是先关闭弹窗再弹错误 Toast，用户输入丢失，需重新打开弹窗。
2. 行内编辑、换绑、密码修改全部只改内存，刷新恢复原值；README 未说明这一点。
3. 短信 / 邮箱验证码模式没有「获取验证码」按钮，验证码任意非空即可通过。
4. 切换验证方式只清空 `#er-old` 文案，**不移除 `#pw-old` 的 `.bad` 红框**。
5. 眼睛图标始终是「闭眼（带斜杠）」图形，只靠透明度区分显隐；在原密码框切到明文后再切到短信模式再切回，type 恢复为 `password` 但眼睛透明度仍为 `.9`。
6. 新密码不 trim、验证项 trim，处理不一致；首尾空格会计入新密码长度。
7. 新旧密码相同不拦截；原密码不校验正确性。
8. 新密码与确认密码均为空时确认密码不报错。
9. 通知邀请页签点击只换高亮不过滤；`rows` 非空时页面空白（无行模板）；页签数字取自独立的 `all/done/todo` 字段，可能与 rows 不符。
10. 「规则说明」是信息展示，却带「取消 / 确定」两个按钮。
11. 「当前租户」卡片不显示「当前」标记，而列表中的同一租户显示，信息重复。
12. 换绑手机号只做中国大陆 11 位手机号校验，不支持国际区号（与独立页「租户管理」的区号字段不一致）。
13. 修改姓名后顶栏、问候语同步，但若姓名与租户名相同（当前数据如此），顶栏租户名不随之变化。
14. 业务职责是自由文本，非枚举选择。
15. 提交时 `$$('.ipt')` 会移除页面上所有 `.ipt`（含可能存在的弹窗输入框）的 `.bad`，作用域过大。
