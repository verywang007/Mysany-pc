# 企业服务-用户管理 页面规格

源文件（旧原型，纯 HTML + 原生 JS，本地运行，无网络请求）：

- `企业服务-用户管理.html`：页面骨架（顶栏、侧栏、主区三个容器、弹窗根节点）
- `user-management.js`：全部数据与交互（IIFE，156 行，单行很长）
- `user-management.css`：页面样式；另引用 `app.css`（外壳）、`data.js`（`window.DB`，仅用其中的 `DB.menu`）
- 背景参考：`README.md`「用户管理独立页」、`设备分配与导入-PRD.md` 第三章。PRD 只作参考，本规格以代码为准，不一致处见第 14 节。

文中「原文」均为代码中的字符串，逐字照抄（含全角/半角标点）。

## 1. 页面结构

```
body.user-page-body（overflow:hidden; background:#fff）
├─ header.hd                顶栏（见第 12 节）
├─ aside.sider              侧栏：nav#menu + 底部折叠按钮 #toggle
├─ main.main.user-main      height:100vh; overflow:hidden
│   └─ .user-container      height:calc(100vh - 48px); flex 纵向; padding:16px
│       ├─ #user-filter     查询区 + 工具栏（同一行，左查询、右按钮）
│       ├─ #user-table-wrap 表格（flex:1，内部滚动）
│       └─ #user-pagination 分页（右对齐）
├─ #flyout                  侧栏折叠态浮层
├─ #toasts                  轻提示容器
└─ #user-modal-root         所有弹窗渲染于此（同一时刻只有一个弹窗）
```

- 页面标题（`<title>`）：`用户管理 - MySANY`
- 无页头标题、无面包屑、无页内 tabs。
- 主区不整体滚动；表格在 `.user-table-wrap` 内横向 + 纵向滚动。
- 响应式：`max-width:1200px` 时查询区换行，按钮组独占一行并右对齐，表格 `margin-top:8px`。

## 2. 查询区（`#user-filter` 左侧 `.user-filter-left`）

无「查询 / 重置」按钮，**所有条件实时生效**（输入框 `input` 事件、下拉 `change`/`input` 事件），每次变更都把页码重置为 1 并只重绘表格与分页。

| 顺序 | 控件 | placeholder / 空选项原文 | 选项来源 | 匹配规则 |
|---|---|---|---|---|
| 1 | 文本输入框 `data-filter="query"`，宽 230px | `搜索姓名、手机号、邮箱` | — | 将 `name`、`phone`、`email` 以空格拼接后转小写，`indexOf(关键字小写) > -1`（模糊、大小写不敏感）。**不匹配**区号 `prefix`、用户名 `username` |
| 2 | 下拉 `data-filter="org"`，宽 170px | 空值选项文案：`选择组织` | 常量 `ORGANIZATIONS`：`2603181012测试客户`、`测试组织1`、`测试组织2`、`aa` | `u.orgs` 包含所选值 |
| 3 | 下拉 `data-filter="role"`，宽 170px | 空值选项文案：`全部角色` | 常量 `ROLES`：`管理员`、`车队长`、`维修工`、`机手` | `u.roles` 包含所选值 |
| 4 | 下拉 `data-filter="scope"`，宽 170px | 空值选项文案：`设备类型` | 固定：`全部设备`、`组织+项目`、`个人设备`（option 的 value 即中文名） | 中文名经 `scopeCode` 转码：`全部设备→'0'`、`组织+项目→'1'`、`个人设备→'2'`，与 `u.deviceScope` 全等比较 |

- 控件高 34px，边框 `#d7dae0`，圆角 4px，文字 `#30364a`；聚焦时边框 `var(--theme)`（#C6000B）+ `box-shadow:0 0 0 2px rgba(198,0,11,.07)`。
- 四个条件为「且」关系。
- 查询条件仅存于内存 `state.filters = { query:'', org:'', role:'', scope:'' }`，刷新页面后清空；保存/删除/导入等操作后会重绘查询区，但值保留。
- 注意：「设备类型」下拉的空选项文案是 `设备类型`，而选项内含 `全部设备`（这是一个具体值 `'0'`，不是「不限」）。

## 5. 分页（`#user-pagination`）

位于表格下方，`min-height:55px`，右对齐，元素间距 8px，文字 `#30364a`。从左到右：

1. 文案：`显示第 {from} 到 {to} 条，共 {total} 条记录`（`total=0` 时 from=0、to=0）
2. 上一页按钮 `‹`（第 1 页禁用）
3. 页码按钮 `1 … N`：**全部页码逐个渲染，无省略**；当前页红底白字；总数为 0 时仍显示页码 `1`
4. 下一页按钮 `›`（最后一页禁用）
5. 每页条数下拉：`10 条/页`、`20 条/页`、`50 条/页`，**默认 10**；切换后回到第 1 页

- 页码按钮：`min-width:30px; height:30px`，边框 `#d9dce2`，圆角 4px；禁用态文字 `#c9cbd1`、底 `#fafafa`。
- 无跳页输入框。页码与每页条数都不持久化。
- 删除用户后：页码取 `min(当前页, 新的最大页)`；新增/编辑/导入用户后：页码重置为 1。

### 6.2 校验（点「保存」时一次性校验全部字段，先清空所有错误文案）

错误文案显示在字段下方（`.um-error`：红 `#f5222d`、12px、`min-height:17px`）。

| 顺序 | 条件 | 错误文案原文 | 显示位置 |
|---|---|---|---|
| 1 | 姓名 trim 后为空 | `请输入姓名` | 姓名下 |
| 2 | 姓名包含特殊字符（正则 ``/[`~!$%^*\|\\=?;:'"<>{}\[\]\/]/``，即 `` ` ~ ! $ % ^ * \| \ = ? ; : ' " < > { } [ ] / `` 任一） | `姓名不能包含特殊字符` | 姓名下 |
| 3 | 手机号与邮箱（trim 后）均为空 | `手机号、邮箱至少填写一项` | 手机号下 |
| 4 | 邮箱非空且不匹配 `/^[^\s@]+@[^\s@]+\.[^\s@]+$/` | `请输入有效邮箱` | 邮箱下 |
| 5 | 所属组织未选 | `请选择所属组织` | 所属组织下 |
| 6 | 分配角色未选 | `请选择角色` | 分配角色下 |
| 7 | （仅新增）初始密码不满足强度规则 | `密码需为6-32位，并包含至少3类字符` | 初始密码下 |
| 8 | （仅新增）确认密码为空或与初始密码不同 | `两次输入的密码不一致` | 确认密码下 |

- 密码强度 `strongPassword`：长度 6–32，且在「小写字母 / 大写字母 / 数字 / 其他字符」4 类中至少包含 3 类。
- **手机号无格式/长度校验**；姓名无长度限制；未校验手机号/邮箱是否与已有用户重复。
- `#@&()-_+,.` 等字符在姓名中是允许的。
- CSS 里定义了 `.um-field.bad`（红边框）但代码从未添加该类，校验失败时输入框边框不变红。

### 6.3 保存逻辑

- **设备范围类型由角色自动推导**（表单中无此字段）：角色含 `管理员` → `'0'`（全部设备）；否则含 `机手` → `'2'`（个人设备）；否则 → `'1'`（组织+项目）。
- **业务职责虽为多选，只保存第一个选中值**（`selectedValues(...)[0] || ''`）。
- 新增：`id = 'u-' + Date.now()`，`username = name`，`created = 当前时间`，`assignedDevices = []`，`personalDevices = []`，`forcePassword = 复选框勾选状态`；插入列表最前（`unshift`）。**初始密码本身不保存**。
- 编辑：覆盖 name、username（=name）、prefix、phone、email、orgs、roles、deviceScope、responsibility；不改 created、forcePassword、设备数据。
- 保存后：写 localStorage → 关弹窗 → 页码重置 1 → 重绘 → toast：新增 `用户新增成功`，编辑 `用户信息已保存`。
- `forcePassword` 在代码其他地方未被读取（「首次登录强制改密」的实际登录行为代码中未体现）。

## 7. 重置密码弹窗（两步）

- 宽 440px（`.um-modal.small`）。
- 标题（两步相同）：`重置'{姓名}'密码`（**半角单引号**）。

**第 1 步：管理员身份验证**

- 蓝色提示条（`.um-info-tip`：文字 `#2c7df0`、底 `#e8f4ff`、13px）：`请输入密码验证管理员身份`
- 字段：`管理员密码`（必填 `*`），密码框 `#reset-admin`，placeholder `请输入`
- 按钮：`取消`、`确定`（主）
- 校验：为空 → `请输入管理员密码`。**只判断非空，任意非空值都视为验证通过**，进入第 2 步。

**第 2 步：设置新密码**

- 字段：`新密码`（必填，`#reset-new`，placeholder `请输入`）、`确认密码`（必填，`#reset-confirm`，placeholder `请输入`）
- 按钮：`取消`、`确认重置`（主）
- 校验（按顺序，遇错即返回）：
  1. 新密码不满足强度规则 → `密码需为6-32位，并包含至少3类字符`
  2. 两次不一致 → `两次输入的密码不一致`
- 成功：给该用户写入 `passwordUpdatedAt = 当前时间`，保存 → 关弹窗 → toast `密码重置成功`。新密码本身不保存；不修改 `forcePassword`。

## 8. 删除用户弹窗

- 宽 440px，标题 `删除用户`。
- 正文：
  - 粗体（15px，`#252b3d`）：`确认删除用户“{姓名}”吗？`（**全角弯引号**）
  - 第二行：联系方式——有手机号显示 `prefix phone`，否则显示邮箱，都无显示 `-`
  - 红色提示块（文字 `#9f2f36`、底 `#fff0f1`）：`删除后，该用户将无法继续访问当前租户，且此操作不可撤销。`
- 按钮：`取消`、`删除`（危险按钮：底/边框 `#ef4450`，白字）
- 确认后：从列表移除 → 保存 → 关弹窗 → 修正页码 → 重绘 → toast `用户“{姓名}”已删除`
- 前置拦截：`id === 'u0'` 时 toast（err 类型）`当前登录用户不能删除`，不弹窗。
- 删除不影响邀请记录。

## 9. 邀请管理

### 9.1 邀请用户弹窗（工具栏 `⌄` → `邀请用户`）

宽 600px（默认），标题 `邀请用户`，两步（同一弹窗内切换）。

**第 1 步：查找用户**

- 分段切换按钮（`.um-segment`）：`手机号` | `邮箱`，默认 `手机号`；选中项边框和文字为 `var(--theme)`。切换会重绘弹窗（输入内容清空）。
- 搜索行：
  - 手机号模式：区号下拉 `#invite-prefix`（宽 160px，选项 `+86`、`+49`、`+62`）+ 输入框 + `搜索`（主按钮）
  - 邮箱模式：无区号下拉，输入框 + `搜索`
  - 输入框 placeholder：手机号模式 `请输入完整手机号`，邮箱模式 `请输入完整邮箱`
- 帮助文案：`请输入已注册 MySANY 账号的完整手机号或邮箱。演示联系人：13341312180 / invite@example.com`
- 底部按钮：`取消`、`发送邀请`（**第 1 步始终 disabled**，禁用样式为浅粉底 `#f8d7d9`、白字）
- 搜索逻辑：在常量 `INVITE_CANDIDATES` 中**精确全等**匹配 `phone`（手机号模式）或 `email`（邮箱模式），trim 后比较；**区号不参与匹配**。不支持回车触发（仅点击「搜索」）。
  - 未找到 → 错误文案 `未找到可邀请的用户`
  - 找到 → 进入第 2 步
- 未检查该候选人是否已是本租户用户、是否已有待验证邀请。

## 13. 数据与持久化

### 13.1 localStorage 键

| 键 | 内容 | 读写 |
|---|---|---|
| `ms_user_management_demo` | `{ users: User[], invites: Invite[] }` 的 JSON | 页面启动读取；任何增删改后整体写回（`saveData`） |
| `ms_open` | 侧栏展开分组 key 数组（JSON） | 读；点击分组时写 |
| `ms_collapsed` | `'1'` / `'0'` 侧栏折叠 | 读；启动时与点击折叠按钮时写 |
| `ms_route` | 跳往工作台时的目标路由 key | 仅写 |

初始化逻辑 `loadData()`：读取 `ms_user_management_demo` 并 `JSON.parse`；当结果存在且 `users`、`invites` **都是数组**时使用之；否则（无值、解析失败、结构不符）使用 `DEFAULT_DATA` 的深拷贝（此时**不立即写回**，首次修改时才写入）。无版本号、无「恢复默认数据」入口。设备 `DEVICES`、组织、角色、业务职责、邀请候选人均为代码常量，不持久化。

### 13.2 数据结构

**User**（由工厂函数 `U(id, name, prefix, phone, email, orgs, roles, scope, duty, created, devices)` 生成）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | 默认数据 `u0`–`u12`（无 `u11`）；新增 `u-{时间戳}`；导入 `imp-{时间戳}-{1/2}` |
| name | string | 姓名 |
| prefix | string | 国际区号，如 `+86`；可为空串 |
| phone | string | 手机号，可为空串 |
| email | string | 邮箱，可为空串 |
| username | string | 恒等于 name |
| orgs | string[] | 所属组织名称 |
| roles | string[] | 角色名称 |
| deviceScope | `'0'｜'1'｜'2'` | 全部设备 / 组织+项目 / 个人设备 |
| responsibility | string | 业务职责（单值），可为空串 |
| created | string | `YYYY-MM-DD HH:mm:ss` |
| assignedDevices | string[] | 已分配设备 id |
| personalDevices | string[] | 个人设备 id；工厂函数中 `scope==='2'` 时取 `devices` 的第 1 个，否则 `[]` |
| forcePassword | boolean | 工厂函数默认 `false`；仅新增时按复选框覆盖 |
| passwordUpdatedAt | string（可选） | 重置密码成功后写入 |

**Invite**：`{ id: 'inv-{时间戳}', user: 姓名, contact: phone||email, roles: string[], orgs: string[], remark: string, inviter: '5656', status: 'pending'|'accepted'|'rejected'|'cancelled', time: 'YYYY-MM-DD HH:mm:ss' }`

**Device**（常量 `DEVICES`）：`{ id, name(设备编号), type(设备类型), org(所属组织) }`

### 13.3 示例数据

## 14. 原型中的疑似缺陷或不一致

仅记录，不代表需要修改。

**与 PRD / README 的不一致**

1. PRD 4.1 要求「导入」改名「导入用户」：按钮已改，但弹窗标题仍为 `导入`。
2. PRD 第四章「弹窗内搜索支持回车与「搜索」按钮，搜索词在重新渲染后回显」：本页设备分配弹窗的搜索是逐字实时过滤，无「搜索」按钮、无回车逻辑（回显是有的）。
3. README 写「邀请记录与重新邀请」：代码中没有任何途径产生 `已拒绝` 状态，`重新邀请` 只能对自己「取消邀请」后的记录使用；`已接受` 同样无法产生。
4. README 写「用户导入：模板下载、文件校验预览、导入结果」：实际不读取文件，任何文件都固定生成 2 条成功数据，无失败行。
5. README 写「首次登录强制修改密码」：只保存了 `forcePassword` 字段，代码中无读取或生效逻辑；编辑用户时也看不到或修改不了该项。

**校验与数据**

6. 密码规则（6–32 位、4 类中至少 3 类）与个人中心修改密码（README：8–20 位且含字母+数字）不一致。
7. 手机号无格式和长度校验；示例数据中有 7 位（`1777777`）和 12 位（`176734561122`）手机号。
8. 业务职责控件是多选，但只保存第一个选中值。
9. 编辑一个只有邮箱、没有区号的用户时，区号下拉默认 `+86`，保存后该用户的 `prefix` 会被写成 `+86`（手机号仍为空）。
10. 新增/编辑未检查手机号、邮箱、姓名是否与已有用户重复；导入用户可重复导入同名用户。
11. 设备范围类型完全由角色推导，表单中不可选；多角色时按 管理员 > 机手 > 其他 的优先级。
12. 编辑把角色改离 `机手` 后，`personalDevices` 不会清空；改成 `机手` 时 `personalDevices` 为空。
13. 个人设备「确定」只把设备并入 `assignedDevices`，从已分配栏移走的设备不会从 `assignedDevices` 删除。
14. 个人设备「可分配设备」列出全部 12 台，不按用户所属组织过滤；批量设备分配也不限制组织，也不区分用户设备范围类型。
15. 「当前登录用户不能删除」按 `id === 'u0'` 判断，而不是按当前登录身份；u0 的「删除」按钮照常显示。

**重置密码**

16. 管理员密码只校验非空，任意值都通过。
17. 第 2 步校验前不清空旧错误：先触发「密码需为…」再触发「两次输入的密码不一致」时，两条错误会同时显示。
18. 重置成功后不设置 `forcePassword`，新密码也不保存。

**邀请**

19. 搜索时手机号区号下拉不参与匹配；邀请弹窗区号只有 3 个（`+86/+49/+62`），新增用户弹窗有 5 个。
20. 帮助文案的演示联系人 `13341312180 / invite@example.com` 分别属于两个不同候选人（陈凯歌 / 李晓明）。
21. 按邮箱搜到候选人后，卡片和记录中的联系方式仍显示手机号（`phone || email`）。
22. 未拦截已是租户成员或已有待验证邀请的用户，可重复邀请。
23. 「取消邀请」「重新邀请」都无二次确认、无 toast。
24. 邀请记录的时间筛选下拉不起作用，重绘后回到 `全部时间`；无分页；`contact` 不展示。
25. 邀请人写死 `'5656'`。
26. 邀请弹窗字段顺序（角色→组织）与新增用户（组织→角色）相反；错误文案 `请选择组织` 与新增用户的 `请选择所属组织` 不一致。

**导入**

27. 用户导入模板 CSV 无 BOM（Excel 打开中文可能乱码），导入分配模板有 BOM；用户导入模板无示例行。
28. 用户导入模板表头（`姓名,国家区号,手机号,邮箱,用户编号,角色`）与预览表列（`行号/用户名/姓名/用户编号/角色/状态`）**已对齐**（本项目 2026-10-16 调整，原型的第 5 列是「所属组织」）；「用户名」「姓名」两列显示同一值；多角色只显示第一个。
29. 上传框文案写「拖放文件到此处」，但未实现拖放；文案说「Excel 模板」，下载的却是 CSV。
30. 选择文件后无法重新选择文件，只能取消重开。
31. 导入分配预览中的「所属组织」取的是设备的所属组织，不是用户的；保存时按姓名匹配用户，同名用户只会匹配第一个；「所属组织」「型号」列不参与匹配。
32. 导入分配在用户列表为空时生成 0 行，停留在上传框，无提示。

**列表与交互**

33. 业务职责为空时显示空白，其他空字段显示 `-`。
34. 分页渲染全部页码，无省略号，页数多时会很长。
35. 查询区「设备类型」下拉的空选项叫 `设备类型`，而 `全部设备` 是一个具体筛选值，容易误解为「不限」。
36. 校验失败时字段不变红（`.bad` 样式已定义但未使用）。
37. 弹窗内每次输入/勾选都整体重建 DOM 并重新聚焦首个输入框：搜索框逐字输入时光标位置、中文输入法组合可能受影响；勾选复选框后焦点也会跳回搜索框。
38. 弹窗不支持点击遮罩关闭（与 wb.js 简易弹窗行为不同）。
39. 批量设备分配成功后，主列表没有任何列体现分配结果（`assignedDevices` 只在批量分配第 1 步的「当前设备数」可见）。

**外壳**

40. 本页未引入 `cookies.css`，toast 没有卡片样式（底色、阴影、内边距）。
41. 顶栏租户、用户名写死（`2603181012测试客户` / `5656`），与工作台从 `data.js` 读取的值（`旺是旺旺的旺`）不一致；语言下拉点击无效果；铃铛只弹提示。
42. 用户下拉为「个人中心 / 返回工作台 / 退出登录」，缺少工作台的「设置」；退出登录无确认。
43. 侧栏缺 `lift` 图标，「吊装规划」显示兜底图标；进入页面时强制展开「企业服务」，但不写回 `ms_open`。
