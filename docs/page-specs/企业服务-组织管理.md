## 3. 数据与持久化

### 3.1 localStorage 键

| 键 | 常量（行号） | 读写 | 内容 |
|---|---|---|---|
| `ms_org_management_demo` | `STORE_KEY`（L100） | 本页读写；`tenant-management.js` 也读写（转让租户负责人时改写 `[0].leaderId`） | 组织树数组 JSON（结构见 3.2） |
| `ms_tenant_owner_id` | `TENANT_OWNER_KEY`（L101） | 本页只读；租户管理页写入 | 租户负责人用户 id，如 `'u0'` |
| `ms_open` / `ms_collapsed` / `ms_route` | — | 外壳 | 见第 2 节 |

### 3.2 组织节点结构（`state.organizations`，树形数组，只有一个根）

```js
{
  id: 'root' | 'org-1' | 'org-<Date.now()>',
  name: string,
  code: string,            // 根为 '-'
  parentId: string|null,   // 根为 null；仅写入，代码中查父节点用 findParentNode 遍历，不读 parentId
  creatorId: string,       // 用户 id
  leaderId: string,        // 负责人用户 id
  description: string,     // 空描述存为 '-'
  root?: true,             // 仅根节点
  members: [{ userId: string, joined: 'YYYY-MM-DD' }],
  devices: [deviceId],     // 本组织直接拥有的设备 id
  deviceDates: { [deviceId]: 'YYYY-MM-DD' },  // 分配时间
  children: [节点...]
}
```

注意：成员、设备都只挂在各节点自身，**不向上汇总**；根组织「设备分配」页签是对全局 `DEVICES` 的视图（见 7.1）。

### 3.3 初始化 `loadOrganizations()`（L116-122）

1. 读 `localStorage['ms_org_management_demo']`，`JSON.parse`；若是**非空数组**则使用它，否则（不存在 / 空数组 / 解析异常）使用 `clone(DEFAULT_ORGS)`。
2. 均经过 `normalizeOrganizations()`（L103-115）递归补全：
   - 缺省 `children/members/devices` → `[]`，`deviceDates` → `{}`；
   - 无 `creatorId`：根 → `'u0'`（`CURRENT_USER_ID`），非根 → `leaderId || 'u0'`；
   - 无 `leaderId` → `creatorId`；
   - **根节点**：若 `ms_tenant_owner_id` 有值，`leaderId` 强制覆盖为该值（每次加载都覆盖）。
3. 加载时**不写回** localStorage；仅在业务操作后 `saveOrganizations()`（L142）整树写入。

### 3.4 重置逻辑

代码中未提供任何「重置演示数据」入口。恢复默认数据只能手动删除 `ms_org_management_demo`（或写入空数组）后刷新。

### 3.5 写入时机

| 操作 | 是否 `saveOrganizations()` |
|---|---|
| 创建 / 编辑组织 | 是 |
| 删除组织 | 是 |
| 添加成员、单个/批量移除成员 | 是 |
| 子组织「分配设备」确定 | 是 |
| 根组织两步向导「确认分配」 | 是 |
| 单个/批量取消分配 | 是 |
| 导入设备「保存导入」 | 是 |
| **根组织行内「分配」→ 选择组织 → 确定** | **否**（L736-740，见缺陷） |

## 5. 组织树

### 5.1 渲染（`renderTree` L296-302，`renderTreeBranch` L284-295）

- 每个节点：`.org-node[role=treeitem]` > `.org-node-row`（高 40px，`padding-left = 8 + depth*18` px，根 depth=0）。
- 行内依次：
  1. 展开按钮 `.org-node-toggle`（24×40，chevron 图标 13px，展开时 `rotate(90deg)`，过渡 .18s）—— **仅当有（过滤后的）子节点时**出现；否则为 24px 占位 `.org-node-spacer`；
  2. 名称 `.org-node-name`（14px，单行省略，`title` 为全名）；
  3. 操作按钮 `.org-node-action`（28×28，图标 16px）：
     - 根节点：「+」，`title="创建组织"`，`aria-label="创建子组织"`，点击直接打开「创建组织」弹窗（父组织 = 根）；
     - 非根节点：「⋮」，`title="更多操作"`，点击弹出节点菜单（5.4）。
     - 默认 `opacity:0`；行 hover、行选中、菜单展开（`aria-expanded="true"`）时 `opacity:1`。
- `aria-expanded`：有子节点时为当前展开态，否则 `"false"`。

### 5.2 展开 / 收起

- 点击 toggle：在 `state.expanded` 中增删该 id 并重渲染树；`stopPropagation`，不触发选中。
- 新建子组织后自动把父节点加入 `expanded`（L681）。
- 搜索词非空时，**所有节点强制展开**（`open = state.treeSearch ? true : ...`），此时点 toggle 只改 `expanded`，视觉上无变化。

### 5.3 搜索与高亮

- `#org-search` 每次 `input` 即时过滤（无防抖、无按钮）；比较前 `trim()`，不区分大小写，子串匹配 `name`。
- 过滤规则 `filteredNode`（L279-283）：节点保留条件 = 搜索为空 **或** 自身名称命中 **或** 有命中的后代。保留的节点**只带命中/含命中的子节点**（命中的父节点下未命中的子节点会被隐藏）。
- 高亮 `highlight`（L273-278）：只包第一个命中位置为 `<mark>`，样式 `color: var(--theme)`（#c6000b）、背景透明。
- 无结果：`.org-tree-empty`（padding 70px 14px，13px，灰色）显示「未找到匹配的组织」换行 + 链接按钮「清除搜索」；点击清空搜索、重渲染、聚焦搜索框。
- 搜索不影响当前选中组织和右侧内容（选中节点可能在树中被过滤掉）。

### 5.4 节点菜单（非根节点「⋮」）

- `.org-node-menu`，`position:fixed`，宽 152px，z-index 350，挂 body；位置 `left = min(innerWidth - 菜单宽 - 8, 按钮right + 3)`，`top = min(innerHeight - 菜单高 - 8, 按钮top)`。
- 三项（高 34px，图标 15px）：「编辑」、「添加子组织」、「删除」（`.danger`，色 #d7000f）。
- 点菜单外任意处关闭；同一时间只有一个菜单；Esc 不关闭菜单。
- 「编辑」→ 编辑组织弹窗；「添加子组织」→ 以该节点为父的创建组织弹窗；「删除」→ 删除流程（第 6.3 节）。
- **根节点没有编辑、删除入口**。

### 5.5 选中

- 点击行（非 toggle / 操作按钮）→ `selectOrganization(id)`（L345）：设 `selectedId`，页签重置为「组织成员」，清空两类勾选，两类页码置 1，整页重渲染。重复点击已选中节点也会执行上述重置。
- 选中样式：背景 #fde7e8，文字 `var(--theme)`；hover 背景 #f5f5f5。

### 6.2 负责人规则

- `ownerUser(node)` = `findUser(leaderId)` → 否则 `findUser(creatorId)` → 否则 u0。
- 新建组织：`creatorId = leaderId = 'u0'`（当前用户），即「创建者自动担任负责人」。**创建者不会被自动加入成员列表**。
- 根组织负责人：加载时若存在 `ms_tenant_owner_id` 则以其为准（由租户管理页转让负责人写入）。
- 本页**没有修改/转让负责人的入口**；表单中负责人为只读展示。
- 成员列表中，`node.leaderId === 用户id` 的行在姓名后显示「人」徽标（见 7.2）。负责人若不是成员则列表中看不到他。
- 负责人可以被当作普通成员移除，无任何拦截；移除后信息卡仍显示其为负责人。

### 6.3 创建 / 编辑组织弹窗（`orgFormHtml` L498-507，`saveOrgForm` L668-684）

入口：根节点「+」（创建，父=根）；非根节点菜单「添加子组织」（创建，父=该节点）；「编辑」（编辑该节点）。

- 宽 600px。标题：创建为「创建组织」，编辑为「编辑组织」；右上「×」关闭（aria-label「关闭」）。

| 字段 | 控件 | 规则 |
|---|---|---|
| 组织名称（必填，红色 `*`） | `input#org-form-name`，`maxlength="64"`，placeholder「请输入」 | 编辑时回填 `name` |
| 上级组织 | `input#org-form-parent`，**disabled** | 创建：父节点名称；编辑：父节点名称，无父时显示「根组织」 |
| 组织负责人 | 只读灰底块（#f7f8fa，padding 12px 14px）：`姓名 | 手机号` | 创建：u0（5656 | 19955665566）；编辑：`ownerUser(node)`。下方说明「组织负责人由创建者自动担任。」（12px #8a91a0） |
| 组织描述 | `textarea#org-form-desc`，`maxlength="200"`，placeholder「请输入」，高 104px，可纵向拉伸 | 编辑时回填（原值为 `-` 时显示为空）；右下角计数「N / 200」，随输入实时刷新 |

底部按钮：「取消」、「保存」（primary）。

保存校验（按顺序，命中一条即停；错误显示在组织名称下方 `.org-field-error`，12px #f5222d）：

1. `name.trim()` 为空 → 「请输入组织名称」，输入框加 `.bad`（红框 #f5222d）；
2. 长度 > 64 → 「组织名称不能超过 64 个字符」（不加红框）；
3. 含禁止字符（正则 ``/[`~!$%^*|\\=?;:'"<>{}\[\]\/]/``，即 `` ` ~ ! $ % ^ * | \ = ? ; : ' " < > { } [ ] / ``）→ 「组织名称不能包含特殊字符」（不加红框）。允许 `@ # & ( ) - _ + , .` 空格及中文全角符号等。
- 无重名校验；描述无校验，`trim()` 后为空存 `'-'`。
- 每次点保存先清空错误与红框；输入过程中不实时校验。Enter 不提交。

保存成功：
- 编辑：改 `name`、`description`，toast「组织信息已保存」。
- 创建：新节点 `id = 'org-' + Date.now()`，`code = 'MYSANY' + 今日YYYYMMDD + Date.now() 末 6 位`，`parentId = 父id`，`creatorId/leaderId = 'u0'`，`members/devices/children = []`，`deviceDates = {}`；追加到父节点 `children` 末尾；父节点展开；**选中新节点**、页签设为「组织成员」；toast「组织创建成功」。

## 10. 弹窗通用规则

- 遮罩 `.org-mask`：fixed 全屏，rgba(0,0,0,.44)，z-index 500，内容居中，padding 24px。**点击遮罩不关闭**。
- 弹窗 `.org-modal`：默认宽 600px，最大 `calc(100vw-48px)` × `calc(100vh-48px)`，圆角 4px，阴影 `0 10px 36px rgba(0,0,0,.25)`，入场动画 .16s（scale .98 + 上移 6px → 原位）。
- 宽度：表单 600；确认 420；选择组织 460；分配设备（子组织）800；添加成员 / 设备分配向导 / 导入设备 870。

- 关闭方式：「×」、「取消」、按 **Esc**（任意弹窗，包括确认框）。
- 每次 `renderModal` 后 20ms 自动聚焦弹窗内第一个非禁用 `input/select`（勾选复选框也会触发重渲染并把焦点拉回搜索框）。
- 确认弹窗 `confirmHtml`：`role="alertdialog"`，标题前黄色圆形「!」（22px，#faad14），内容 #555d70 行高 1.8；按钮「取消」+ 红色 danger 确认按钮（文字由调用方传入，缺省「确认」）。点确认先关弹窗再执行回调。

## 14. 原型中的疑似缺陷或不一致（仅记录）

### 14.1 代码自身

1. **行内「分配」不持久化**：选择组织弹窗「确定」（L736-740）只 `assignDevicesTo` + `renderPage`，未调用 `saveOrganizations()`；刷新后丢失，除非之后有其他保存操作把整树写回。
2. **toast 无样式**：页面未引入 `cookies.css`，而 `.toast` 的底色、阴影、padding、字号都定义在 `cookies.css`；`organization.css` 只给了 `min-width` 和 `justify-content`。toast 实际渲染为无背景的纯文字；`ok/info/err` 类型也无任何视觉区分，且不带图标。
3. 组织名称 `maxlength="64"` 导致「组织名称不能超过 64 个字符」实际无法触发；超长与特殊字符两种错误不加红框，只有空值加红框。
4. 组织名称无重名校验；而导入按「所属组织」名称匹配第一个同名组织，重名时会分配到错误组织。
5. 新建组织编码 = `MYSANY + 日期 + Date.now() 末 6 位`，与示例数据的流水号形式（000142、000143）不同，理论上可重复。
6. 创建组织后直接改 `selectedId` 并设 tab，**未清空勾选、未重置页码**；删除组织后跳父节点同样未重置。若之前成员页在第 2 页，新组织会显示空页且「0 条记录」、无高亮页码、「‹」可点。
7. 移除成员 / 取消分配后页码不回收：删空最后一页后仍停留在空页。
8. 删除任意非当前选中的组织后，选中也会被强制切到其父节点。
9. 搜索时所有节点强制展开，toggle 按钮可点但无效果；命中的父节点下未命中的子节点被隐藏；高亮只标第一个命中处；当前选中节点可能被过滤掉而右侧仍显示它。
10. 只勾 1 项后点批量按钮，弹窗仍为「批量移除」/「确认移除选中的 1 名组织成员吗？」（批量取消分配同理）。
11. 根视图下批量勾选包含未分配设备时，按钮显示的 N 与确认框中的台数 M 不一致（M 只计已分配）。
12. 取消分配确认框按钮为「取消」与「取消分配」并列，语义易混。
13. 负责人不会自动成为成员；负责人可被移除且无提示；根组织负责人 u0 默认不在根成员列表，org-2、org-3 负责人也都不是本组织成员。
14. 两步向导第 1 步「当前设备数」用 `node.devices.length`，根组织显示 0（而非租户全部设备数）。
15. 两步向导第 2 步可勾选已属于目标组织的设备，确认后其分配时间被刷新为今天；第 2 步无分页、无全选。
16. 两步向导中搜索框未提交的输入，在勾选/切换 radio 触发重渲染时被重置为上次提交的搜索词（成员/子组织设备弹窗有 `searchInput` 保留，向导没有）。
17. 弹窗内每次勾选都整窗重渲染并把焦点拉回第一个输入框（搜索框），表格滚动位置也会复位。
18. 弹窗点击遮罩不关闭；Esc 可关闭包括确认框在内的所有弹窗；Esc 不关闭树节点菜单。
19. 导入：文案写「拖放文件到此处」但无 drop 事件处理，点击虚线框本身也无效，只能点「选择文件」；不解析文件内容，结果固定为前 3 台未分配设备、失败恒为 0；选择文件后无法重新选择；`URL.revokeObjectURL` 在 `a.click()` 后立即调用。
20. 子组织视图也能「导入」，导入结果可能把设备分配到其他组织，当前子组织列表看不到变化。
21. 主设备列表与成员列表都没有列表级搜索。
22. 主列表分页渲染全部页码，无省略；表头复选框无半选态。
23. `assignHtml` 中弹窗「×」缺 `aria-label`（其他弹窗有）。
24. 外壳：语言、租户下拉项点击无反应；退出登录无确认；`ICONS` 缺 `lift`，「吊装规划」菜单图标回退为 `box`；`ent` 图标与 wb.js 不同（详见第 2 节）。
25. `parentId` 只写不读；成员 `joined` 与分配时间使用浏览器本地日期。

### 14.2 PRD 与代码不一致

1. PRD 涉及页面路径写作 `Mysany-pc/mysany-login-local/企业服务-组织管理.html`，实际文件位于 `Mysany-pc/` 根目录。
2. PRD 3.4：确认后提示「设备已分配到「组织名」」（直角引号）；代码为「设备已分配到“组织名”」（弯引号）。
3. PRD 3.4 / 3.5 均描述确认后「列表实时刷新」，未提及持久化差异；代码中单台分配不写 localStorage（见 14.1-1），与 PRD 4「所有变更写入 localStorage」不符。
4. PRD 3.5 注：子组织「分配设备」弹窗「分页 10/20/50」；代码弹窗分页仅 10/20。
5. PRD 3.5 注：子组织分配「单击即分配至当前组织」；代码需勾选后点「确定」。
6. PRD 3.6：模板为「标准的 Excel 模板」字样出现在上传说明中，而实际下载为 `.csv`（PRD 表格本身写的是 csv，与代码一致；上传框文案与下载格式不一致）。
7. PRD 3.6 校验结果「成功 N 条，失败 0 条」描述为校验结果；代码并不读取文件，结果为演示数据生成。
8. README 写「设备分配：已分配设备列表、分配设备、单个 / 批量取消分配、搜索与分页」；主列表无搜索，搜索只在分配弹窗中。
9. PRD 3.3 写「子组织：统一为 取消分配」与代码一致；但 PRD 3.2「所属组织：子组织展示本组织名称」——代码实际取 `deviceOwnerOrg` 深度优先第一个命中的组织，正常数据下等价，代码中未体现对同一设备被多个组织同时持有的防护。
