## 3. 筛选区

| 顺序 | 控件 | 属性 | placeholder / 首项 | 选项（value → 文案） |
|---|---|---|---|---|
| 1 | `input.rm-input[data-role-filter=name]` | 宽 240、高 34 | `请输入角色名称` | — |
| 2 | `select.rm-select[data-role-filter=type]` | 宽 240、高 34 | `请选择角色类型`（value 空） | `custom` → 自定义；`system` → 系统配置 |
| 3 | `select.rm-select[data-role-filter=scope]` | 宽 240、高 34 | `请选择设备权限类型`（value 空） | `0` → 全部设备；`1` → 组织+项目；`2` → 个人设备 |
| 4 | `button.rm-btn.primary[data-add-role]` | — | `新增角色` | 打开「新增角色」弹窗 |

规则：
- **实时筛选**：input 的 `input` 事件、select 的 `change` 事件都立即写入 `state.filters` 并 `page = 1` 后重渲染列表。无「查询 / 重置」按钮。
- 名称：`r.name.toLowerCase().indexOf(q.toLowerCase()) > -1`，不区分大小写的子串匹配；**不 trim**（输入空格也会参与匹配）。
- 类型、设备权限类型：精确匹配 `r.type` / `r.scope`。
- 三个条件为 AND。
- 筛选条件存于内存 `state.filters`，从详情返回列表时保留；刷新丢失。
- 屏宽 ≤ 1050px：筛选行 `flex-wrap: wrap`，「新增角色」取消 `margin-left:auto`。

## 5. 分页（列表）

结构：`{total} 条记录` + `‹` + 页码按钮 1..N + `›` + 每页条数下拉。

- `count = max(1, ceil(total / pageSize))`，页码按钮全部平铺（无省略号）。
- 当前页按钮 `.rm-page.active`：主题红底白字。按钮 30×30、圆角 4、边框 `#d9dce2`。
- `‹` 在 `page <= 1` 时 disabled；`›` 在 `page >= count` 时 disabled。
- 每页条数 `select[data-role-size]`（宽 110、高 30）：`10 条/页`、`20 条/页`；切换后 `page = 1`。
- 默认 `pageSize = 10`，`page = 1`。
- 示例数据共 4 条，默认只有 1 页。

## 6. 新增 / 编辑角色弹窗

外壳 `shell('', title, body, foot)`：`.rm-mask`（fixed 全屏，`rgba(0,0,0,.44)`，z-index 500，padding 24）> `.rm-modal`（宽 520px，max-width `calc(100vw - 48px)`，max-height `calc(100vh - 48px)`，圆角 4）。头部 min-height 58、标题 18px；右上 `×` 关闭（`data-modal-close`）；底部按钮右对齐 gap 10。

- 标题：新增时 **`新增角色`**；编辑时 **`编辑角色`**。
- 入口：列表「新增角色」按钮；自定义角色行的「编辑」。

body 由两个灰底块 `.rm-form-block`（padding 16，圆角 12，背景 `#f8f8f9`）组成：

**块 1**

| 字段 | 必填 | 控件 | 属性 | placeholder | 帮助文字 |
|---|---|---|---|---|---|
| 角色名称 | 是（红 `*`） | `input#rf-name.rm-field`（高 36） | `maxlength=50` | `请输入` | `角色名称在租户内必须唯一` |
| 角色描述 | 否 | `textarea#rf-desc`（高 105，可纵向拉伸） | `maxlength=200` | `请输入` | `描述角色的职能和权限范围` |

**块 2**

设备权限类型（必填，红 `*`）：三张单选卡片 `.scope-option`（竖排，gap 10，padding 13，圆角 7，边框 `#dfe2e7`；选中 `.active` 边框 + 1px 外描边为主题红），每张卡 = radio + 粗体标题 + 灰色说明（`#72798a`）：

| value | 标题 | 说明（原文） |
|---|---|---|
| `0` | 全部设备 | 用户可查看租户内所有设备，无需额外分配。适用于管理员、总监等高层管理人员。 |
| `1` | 组织+项目 | 用户可查看其所属组织和加入项目的设备，自动计算权限。适用于区域经理、项目经理等中层管理人员。 |
| `2` | 个人设备 | 用户只能查看特定分配的设备，需要管理员手动分配。适用于普通操作员、机手、维修工等基层人员。 |

- 新增时默认不选中任何项；编辑时回填当前 scope。
- 切换 radio 时只切换 `.active` 类，不重渲染弹窗（并把当前输入值暂存到 `state.modal.draftName/draftDesc`）。

底部按钮：`取消`（关闭）、`保存`（primary，`data-save-role`）。

**校验（点「保存」时，逐字）**——错误显示在字段下方 `.rm-error`（12px，`#f5222d`，min-height 17）：

| 条件 | 位置 | 文案 |
|---|---|---|
| 名称 trim 后为空 | 角色名称下 | `请输入角色名称` |
| 已存在 `r.name === name && r.id !== 当前id`（trim 后、区分大小写全等） | 角色名称下 | `角色名称已存在` |
| 未选设备权限类型 | 设备权限类型下 | `请选择设备权限类型` |

- 每次保存先清空所有错误再重新校验；多个错误同时显示。
- 输入时不实时校验、不清错误。
- 描述 trim 后保存。

**保存成功**：
- 新增：`unshift` 新对象 `{id:'r-'+Date.now(), name, type:'custom', description, scope, assignedUserIds:[], created: 当前时间 'YYYY-MM-DD HH:mm:ss', permissions:[], defaultPermissions:[]}`。
- 编辑：只改 `name / description / scope`，不动权限、用户。
- 然后写 localStorage → 关闭弹窗 → `page = 1` → 渲染列表（**筛选条件不清空**）→ toast：新增 `角色新增成功`，编辑 `角色信息已保存`。

弹窗打开后 15ms 自动聚焦第一个 input（角色名称）。回车无提交行为。

## 7. 确认类弹窗（`openConfirm`）

外壳同上，`.rm-modal.small` 宽 430px；body 为 `.rm-confirm-copy`（`#535c70`，行高 1.75）纯文本。底部：`取消` + 确认按钮（`danger` 时红 `#ef4450` 底，否则 primary 主题红）。点击确认按钮：先关闭弹窗，再执行回调。

| 场景 | 标题 | 正文（原文，`{}` 为变量） | 确认按钮 | 样式 | 回调 / toast |
|---|---|---|---|---|---|
| 恢复默认（列表或详情） | `确认恢复默认` | `确认将角色“{name}”的功能权限恢复为系统默认值吗？` | `确认` | primary | `permissions = defaultPermissions.slice()`，写存储；列表来源则重渲染列表，详情来源则同步草稿并重渲染详情；toast `已恢复默认权限` |
| 删除（有关联用户） | `无法删除` | `角色“{name}”已关联 {n} 名用户，请先移除关联用户。` | `知道了` | primary | 空函数（仍有「取消」按钮） |
| 删除（无关联用户） | `确认删除` | `确认删除角色“{name}”吗？删除后不可恢复。` | `删除` | danger | 从数组移除，写存储，重渲染列表；toast `角色已删除` |
| 移除用户角色 | `移除角色` | `确认从用户“{userName}”中移除角色“{roleName}”吗？` | `确认` | danger | 从 `assignedUserIds` 移除，写存储，重渲染详情；toast `角色已移除` |

注意引号均为中文全角 `“”`。

- **点击遮罩不关闭**（无相应处理）。

### 8.4 功能权限页签

顺序：
1. 警示条 `.permission-warning`（黄：边框 `#f4d374`，字 `#7d5b12`，底 `#fff9e7`），原文：
   `● 角色分配解绑权限后，解绑设备会影响整个组织的设备绑定关系，请谨慎分配权限。`
2. 工具条：`input#permission-search`（placeholder `搜索权限`，宽 240）、按钮 `展开全部`、`折叠全部`、`全选/全不选`。
3. 权限树 `.permission-tree`（高 `calc(100vh - 430px)`，min-height 280，自身滚动）。

**树结构**
- 顶层固定一行「根」：一个装饰性的展开箭头（`perm-toggle open`，无 data 属性，点击无效）+ 复选框（`data-perm-check="__all"`）+ 粗体 `应用功能 (12)`（括号内为 `PERMISSIONS.length`，即一级模块数 12，不是总权限点数 60）。根下始终显示一级节点，不可折叠。
- 每个节点行：缩进 `padding-left = depth*26 + 4`px（一级 depth=1）；有子节点显示 `›` 切换按钮（展开时旋转 90°），无子节点显示 22px 占位；复选框 16×16（accent 主题红）；名称。
- 节点是否展开：`state.permSearch`（原始未 trim 的搜索词）非空时**全部展开**；否则看 `state.expanded`。

**勾选规则**
- 节点「勾选」显示条件：自身 id 与全部后代 id 都在草稿中。
- 「半选」：未全选且其中至少一个在草稿中 → 渲染后设置 `indeterminate = true`。根「应用功能」复选框**没有半选态**，仅在 `draft.size === 60` 时勾选。
- 勾选 / 取消某节点：对**自身 + 全部后代**统一加入 / 移除；**不会向上联动父节点 id**（见缺陷）。
- 根复选框：勾选 → 草稿 = 全部 60 个 id；取消 → 清空。
- `全选/全不选` 按钮：若 `draft.size === 60` 则清空，否则全选。

**展开 / 折叠**
- `展开全部`：把所有 60 个 id 加入 `expanded`。
- `折叠全部`：清空 `expanded`（一级节点仍显示，只是都收起）。
- 单节点 `›` 切换 `expanded` 中的该 id。

**搜索**
- `input` 事件实时过滤，每次输入重渲染详情。
- 过滤规则（`filterPerm`，用 trim 后的词）：节点名称不区分大小写包含关键字，或有后代命中 → 保留；保留节点的子节点只保留「自身命中或有后代命中」的子节点。即**命中的父节点若其子节点都不命中，则父节点显示为叶子（子节点被隐藏）**。
- 命中文字高亮：`<mark>`，颜色主题红、背景透明；高亮使用未 trim 的搜索词，只高亮第一处。
- 搜索结果为空时：只显示根行，无空状态文案。

**保存 / 重置 / 恢复默认**
- `保存`：`role.permissions = Array.from(draft)`，写 localStorage，toast `功能权限已保存`。无确认、不判断是否有变化。
- `重置`：草稿恢复为该角色已保存的 `permissions`，无确认、无 toast。
- `恢复默认`（仅系统角色）：走第 7 节确认弹窗；确认后直接写存储（**无需再点保存**），并同步草稿。

## 12. 原型中的疑似缺陷或不一致

1. **实时筛选输入框每输入一个字符就丢焦点**：角色名称、权限搜索、用户姓名三个输入框的 `input` 事件都会整块 `innerHTML` 重渲染（`renderList` / `renderDetail`），输入框被替换，焦点丢失，连续输入需反复点击。
2. **列表每页条数下拉不回显**：`<option>` 未写 `selected`，切换到 `20 条/页` 后重渲染又显示 `10 条/页`（实际 pageSize 已是 20）。
3. **删除后页码不回退**：删除最后一页唯一一条时 `page` 不变，可能显示空表「无结果」而总数不为 0。
4. **权限勾选不向上联动**：逐个勾选某父节点的全部子节点后，父节点 id 本身不在草稿中，父节点仍显示半选；保存的 `permissions` 中也不含该父 id。反之取消全部子节点后，父 id 仍留在草稿里，父节点显示为半选（自身 id 命中）。
5. 根「应用功能」复选框没有半选态；其旁边的展开箭头是装饰性的，点击无效果。
6. `应用功能 (12)` 显示的是一级模块数，不是权限点总数（60）。
7. 初始展开集合含 `'app'`，但不存在 id 为 `app` 的节点（无效值）。
8. 搜索时命中的父节点若子节点都不命中，其子节点被隐藏，父节点显示为叶子；此时勾选父节点会连带勾选所有（不可见的）后代。搜索模式下点击 `›` 无可见效果（搜索时强制全部展开）。搜索高亮用未 trim 的词、过滤用 trim 后的词。
9. 用户分配的搜索框 placeholder 为「请输入用户姓名」，实际同时匹配登录凭证。
10. 用户分配页的分页是静态假分页（固定页码 1、只有「10 条/页」），无交互。
11. 用户分配筛选条件 `userFilters` 进入其他角色详情时不重置。
12. 没有为角色添加/分配用户的入口；新建的自定义角色永远 0 用户，因此删除时「无法删除」分支在原型中实际触发不到（只有手改存储才能触发）；预置角色均为系统角色，没有删除按钮。
13. 「无法删除」提示弹窗同时有「取消」和「知道了」两个按钮，两者效果相同。
14. 离开详情（返回列表）时未保存的权限修改被静默丢弃，无「是否保存」提示；「保存」不判断是否有改动。
15. 「恢复默认」确认后直接持久化，绕过「保存」按钮；与页面上「保存 / 重置」的草稿模式不一致。
16. 筛选条件存在时新增角色，`page` 置 1 但筛选不清，新角色可能不在结果中，用户看不到刚创建的角色。
17. 设备权限类型的 `scopeName` 对 `'0'`、`'1'` 以外的任何值都显示「个人设备」。
18. 角色名称唯一校验区分大小写（`ABC` 与 `abc` 可并存），而列表名称筛选不区分大小写。
19. 点击遮罩不能关闭弹窗（Esc 可以）。
20. 未加载 `cookies.css`，`.toast` 没有背景、内边距、阴影；本页 CSS 中 `.toast{justify-content:center}` 在非 flex 元素上无效；toast 也没有类型图标——提示视觉上只是一行浮动文字。
21. 顶栏：租户名「2603181012测试客户」、用户名「5656」、角标「10」均写死，与工作台（`DB.user.name` / `DB.tenant` 为「旺是旺旺的旺」）不一致；语言、租户下拉点击无反应；退出登录无确认。
22. 本页用户数据中 u0（5656）属「管理员」角色，而组织管理页 `USERS` 中 u0 的角色是「超级管理员」；用户/角色数据在各页各自维护，相互不同步（如在本页移除用户角色，用户管理页不变）。
23. 菜单「吊装规划」在本页显示为 box 回退图标，与工作台不同。
