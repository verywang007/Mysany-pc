## 1. 数据与存储

### 1.1 localStorage 键 `ms_settings`

```ts
type MsSettings = {
  ckNecessary: boolean;   // 必要 Cookie，保存时强制 true
  ckFunctional: boolean;  // 功能 Cookie
  ckAnalytics: boolean;   // 性能 Cookie
  ckAds: boolean;         // 定向 Cookie
  personalAds: boolean;   // 个性化广告
};
```

- 默认值 `SET_DEFAULT`（cookies.js L16–22）：`{ ckNecessary: true, ckFunctional: true, ckAnalytics: true, ckAds: false, personalAds: false }`。
- 读 `MSCookies.load()`：`Object.assign({}, SET_DEFAULT, JSON.parse(localStorage.ms_settings || '{}'))`；解析异常时返回默认值副本。
- 写 `MSCookies.save(s)`：先 `s.ckNecessary = true`，再 `localStorage.ms_settings = JSON.stringify(s)`（整对象写入）。
- 读时机：每次打开设置弹窗（`draft = loadSet()`，wb.js L586）。
- 写时机：
  1. 设置弹窗点「保存」（wb.js L687）；
  2. 在设置弹窗内打开的 Cookie 抽屉里点「全部拒绝」或「确认我的选择」（cookies.js L188–194 `commit`）。
- 登录页（app.js）的 Cookies 入口读写同一个键，两处互相同步。

### 1.2 草稿模型

- 打开弹窗时生成草稿 `draft`（`ms_settings` 的副本），弹窗内所有开关只改 `draft`。
- 「保存」才把 `draft` 写入；其他关闭方式直接丢弃。
- 草稿在「主页 ↔ 协议阅读页」之间切换时保留。

### 2.2 Cookies 状态行

- 位置：第 3 行说明下方 `.set-status`（12px，`--ink-4`，上距 6px）。
- 文案：`已启用 {N} / {总数} 类`，N = `CK_ITEMS` 中 `draft[k]` 为真的个数，总数 = 4。
- `ckNecessary` 恒为 true 计入，因此 N 最小为 1；默认值下显示 `已启用 3 / 4 类`。
- 依据的是**草稿**而非已保存值。

### 2.3 个性化广告开关

- 开关 `.sw`（cookies.css L44–57）：40×22，圆角 11px，关 `#d5d9e0`，开 `--theme`；白色滑块 18×18、`top/left:2px`，开时 `translateX(18px)`，`.2s`；`role="switch"`、`aria-checked`。
- 点击：`draft.personalAds` 取反 → 原地切换 `.on` 与 `aria-checked`（不重绘整个弹窗）。
- 初始状态取自 `ms_settings.personalAds`（默认 `false` = 关）。
- 代码中保留了 `lock` 分支：若开关带 `.lock` 则 Toast（info）`必要 Cookies 无法关闭`；设置弹窗中没有任何 lock 开关，此分支不可达。

### 3.3 阅读页交互

- 返回箭头 / `返回设置` → 回到主页（`page='main'` 重绘；草稿中个性化广告开关状态保留）。
- × / 点遮罩 / Esc → 关闭**整个**设置弹窗（不保存）。
- 阅读页没有「同意」等操作。

## 4. 关闭、保存、取消（wb.js L653–691）

| 操作 | 位置 | 结果 |
|---|---|---|
| `保存` | 主页底部 | `MSCookies.save(draft)`（写 `ms_settings`，强制 `ckNecessary=true`）→ 关闭 → Toast（ok）`设置已保存` |
| `取消` | 主页底部 | 关闭，草稿丢弃，无提示 |
| × | 主页 / 阅读页头部 | 同取消 |
| 点遮罩空白处（`e.target === mask`） | 任意页 | 同取消 |
| Esc | 任意页（document 级 keydown） | 同取消，并移除 keydown 监听 |

- 「保存」写入的是整个草稿（4 个 Cookie 分类 + `personalAds`），不只是个性化广告。
- 保存后无任何页面级生效动作（不影响其他存储读写，代码中未体现按偏好禁用存储）。
- 弹窗不阻止背景滚动（代码中未体现）。

## 5. Cookies 设置入口与抽屉联动（wb.js L671–674，cookies.js L79–252）

- 点击 `设置 ›` → `MSCookies.openDrawer(draft, onDone)`，`onDone = function () { render(); }`。
- 抽屉遮罩 `.dw-mask` 追加到 `body`，z-index 420，盖在设置弹窗（400）之上；设置弹窗保持打开。
- 抽屉内部使用 `draft` 的**副本** `d` 编辑；
  - 「全部拒绝」/「确认我的选择」→ 把 4 个分类值写回 `draft`（`ckNecessary` 强制 true）→ **立即 `save(draft)` 写入 `ms_settings`** → 关闭抽屉 → Toast（`已拒绝全部非必要 Cookie` / `Cookie 偏好已保存`）→ `onDone` → 设置主页重绘，状态行更新；
  - 抽屉 × / 点抽屉遮罩 / Esc → 不写回，关闭抽屉 → `onDone` → 设置主页重绘（数值不变）。
- 「全部允许」只改抽屉内副本并提示 `已允许全部 Cookie`（info），需再点确认才写入。
- 即：Cookie 分类在抽屉里确认即落库，**不受设置弹窗「取消」影响**；个性化广告只能通过设置弹窗「保存」落库。

## 6. 原型中的疑似缺陷或不一致

1. **Esc 双重关闭**：抽屉打开时按 Esc，设置弹窗和抽屉各自的 document keydown 监听都会触发，设置弹窗（先注册）与抽屉同时关闭；抽屉随后回调 `render()` 作用在已移除的遮罩上。
2. **草稿被抽屉连带保存**：抽屉 `commit` 执行 `save(target)`，`target` 就是设置弹窗的整个 `draft`。若用户先切换了「个性化广告」开关（未保存），再在抽屉里确认，`personalAds` 的未保存修改也会被写入 `ms_settings`；之后点「取消」也无法撤销。
3. 设置弹窗「取消」对已在抽屉中确认的 Cookie 偏好无效，同一弹窗内存在两种提交语义（README 有说明「取消不生效」仅指个性化广告）。
4. `lock` 开关分支及 Toast `必要 Cookies 无法关闭` 在设置弹窗中不可达。
5. 文案不一致：行标题为「个性化广告」，隐私协议正文写「个人化广告」，wb.js 注释写「个人化广告」；`AD_DESC` 中品牌名为小写 `sanvist` 且与中文无空格。
6. 隐私协议正文提到「关闭分析类 Cookies」，而 Cookie 抽屉中该分类名为「性能 Cookie」。
7. 默认 `ckAnalytics: true`（性能 Cookie 默认开启），状态行默认 `已启用 3 / 4 类`。
8. `ms_settings` 实际存于 localStorage，而 data.js Cookie 清单称其为 Cookie、持续 180 天。
9. 协议正文是本地示例文本（README 与正文 `.note` 均声明非正式法律文件），版本标注「本地 v1.0」，与 `协议变更.html` 中 v3.2 的版本体系无关联。
10. 简易弹窗（退出登录等）不支持 Esc，而设置弹窗支持，两类弹窗关闭方式不统一。
11. 工作台齿轮 `title="设置"` 但不打开本弹窗。
12. 打开弹窗时无焦点管理，Tab 可跳到背景页面元素（代码中未体现焦点陷阱）。
