## 一、需求背景与目标

### 1.1 背景

1. 手机号、邮箱、用户名（代理商租户才有）是用户的**登录账户**。原实现中编辑用户可随意修改手机号 / 邮箱 / 用户名，账户标识不稳定，存在误改风险。
2. 新增用户时缺少「登录账户信息确定后不可修改」的显式告知，管理员容易填错后才发现无法调整。
3. 手机号输入框下的提示词未说明「登录账户」语义，管理员不知道这两个字段的重要性。

### 1.2 目标

| 目标 | 说明 |
| --- | --- |
| 账户信息一次性设定 | 新增用户时确认后，登录账户信息不可再修改 |
| 编辑防误改 | 已填写的登录账户字段在编辑时锁定（置灰），从 UI 上杜绝修改 |
| 语义清晰 | 手机号下方常驻提示「…为登录账户」，按租户类型区分文案 |
| 操作有告知 | 新增 / 补填登录账户字段时，先弹窗确认再提交 |

---

## 二、登录账户定义与提示词

### 2.1 登录账户字段

| 字段 | 表单控件 | 说明 |
| --- | --- | --- |
| 用户名 | 「姓名」输入框 | 即用户 `name`（保存时 `username = name`） |
| 手机号 | 区号下拉 + 号码输入框 | 含区号整体作为账户信息 |
| 邮箱 | 邮箱输入框 | |

### 2.2 手机号下方常驻提示词（按租户类型）

租户类型取租户管理页「租户类型」字段（`getTenantType()`，字符串含「代理商」即代理商分支）：

| 租户类型 | 提示词 |
| --- | --- |
| 企业客户（默认） | `手机号、邮箱为登录账户，至少填写一项` |
| 代理商 | `手机号、邮箱、用户名为登录账户，至少填写一项` |

## 三、新增用户

1. 底部按钮：`取消`、`确定`（主按钮；原「保存」已改名）。
2. 点「确定」先做整表校验（姓名必填、手机号 / 邮箱至少一项、组织 / 角色必选、初始密码规则等），**校验通过后**弹出确认框：

| 项 | 内容 |
| --- | --- |
| 标题 | `提示` |
| 正文 | `手机号、邮箱、用户名作为登录账户，确定后不可修改。` |
| 图标 | 无 |
| 按钮 | `取消`、`确定`（主） |

3. `取消` → 留在表单，已填内容不丢；`确定` → 提交保存，toast `用户新增成功`。
4. 所有租户类型均弹此确认框（不区分企业客户 / 代理商）。

---

## 四、编辑用户

### 4.1 字段锁定规则

| 字段 | 编辑时状态 |
| --- | --- |
| 手机号 |  非空 → 区号下拉与号码框一起禁用；为空 → 可补填 |
| 邮箱 |  非空 → 禁用；为空 → 可补填 |
| 用户名 | 非空 → 禁用；为空 → 可补填 |

- 禁用控件为置灰态（antd `disabled`），不可聚焦编辑。
- 锁定字段下方帮助文案变为：`已设置为登录账户，不可修改`（手机号、邮箱均适用）。

### 4.2 补填确认

- 编辑时对**原本为空**的手机号 / 邮箱进行了补填，点「确定」（校验通过后）弹出与新增相同的确认框（标题 `提示`，正文 `手机号、邮箱、用户名作为登录账户，确定后不可修改。`，按钮 `取消` / `确定`）。
- 未补填任何登录账户字段（只改组织 / 角色 / 职责等）→ 不弹窗，直接保存。
- 补填后点「取消」→ 留在表单继续编辑；「确定」→ 提交，toast `用户信息已保存`。
- 提交后补填值即成为登录账户的一部分，再次编辑时该字段锁定。

## 七、验收标准

1. 企业客户租户新增用户：手机号下方提示词为 `手机号、邮箱为登录账户，至少填写一项`；点「确定」出现 `提示` 弹窗，正文与按钮符合第三章；取消后表单内容保留，再点「确定」再次弹窗，确认后保存成功。
2. 代理商租户新增用户：提示词为 `手机号、邮箱、用户名为登录账户，至少填写一项`，确认弹窗行为同上。
3. 新增弹窗底部主按钮文案为「确定」。
4. 编辑手机号已填写的用户：姓名、手机号（含区号）均置灰不可编辑，手机号下文案为 `已设置为登录账户，不可修改`；邮箱为空时可填写。
5. 编辑邮箱已填写的用户：邮箱置灰不可编辑；手机号为空时可填写。
6. 编辑时补填空白的手机号或邮箱 → 点「确定」弹出确认框；确认后保存，再次进入编辑该字段已锁定。
7. 编辑时只改组织 / 角色 / 业务职责 → 不弹确认框，直接保存（toast `用户信息已保存`）。
